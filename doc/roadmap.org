#+begin_src scheme
;;; message display
(define *message-last* "")
(define *message-callback* #f)

(define (message fmt . args)
  "Display a message in the message bar."
  (let ((msg (apply format #f fmt args)))
    (set! *message-last* msg)
    (log-info "Message: ~a" msg)
    (when *message-callback*
      (*message-callback* msg))
    msg))

(define (message-no-timeout fmt . args)
  "Display a persistent message."
  (apply message fmt args))

;;; interactive input
(define *input-callback* #f)
(define *input-prompt* "")
(define *input-buffer* "")
(define *input-completions* '())
(define *input-result-callback* #f)

(define* (read-one-line prompt #:key (completions '()))
  "Request one line of input from the user.
In the async architecture, this sets up state and returns #f immediately.
The actual input is handled via handle-input-key callbacks."
  (set! *input-prompt* prompt)
  (set! *input-buffer* "")
  (set! *input-completions* completions)
  ;; display prompt
  (log-debug "~a" prompt)
  ;; return #f, the actual result comes via callback
  #f)

(define (read-yes-or-no prompt)
  "Ask a yes/no question."
  (read-one-line (string-append prompt " (y/n) ")))

(define (handle-input-key key-str)
  "Handle a keypress during input mode. Returns #f or the completed string."
  (cond
   ((string=? key-str "Return")
    (let ((result *input-buffer*))
      (set! *input-buffer* "")
      (set! *input-prompt* "")
      result))
   ((string=? key-str "Escape")
    (set! *input-buffer* "")
    (set! *input-prompt* "")
    (log-debug "Aborted.")
    #f)
   ((string=? key-str "BackSpace")
    (when (> (string-length *input-buffer*) 0)
      (set! *input-buffer*
        (substring *input-buffer* 0 (1- (string-length *input-buffer*)))))
    (log-debug "~a~a" *input-prompt* *input-buffer*)
    #f)
   ((string=? key-str "Tab")
    ;; Tab completion
    (let ((matches (filter (lambda (c)
                             (string-prefix? *input-buffer* c))
                           *input-completions*)))
      (cond
       ((null? matches) #f)
       ((= 1 (length matches))
        (set! *input-buffer* (car matches))
        (log-debug "~a~a" *input-prompt* *input-buffer*)
        #f)
       (else
        (log-debug "~a" (string-join matches " | "))
        #f))))
   ((= (string-length key-str) 1)
    ;; Regular character
    (set! *input-buffer* (string-append *input-buffer* key-str))
    (log-debug "~a~a" *input-prompt* *input-buffer*)
    #f)
   (else #f)))
#+end_src

** settings UIs
maybe it's convenient to have very basic gleui keyboard driven interfaces to manage different part of the desktop stack. I am listing below some ideas that I feel they could be very convenient to have.
NOTE: I won't be including some settings options like output, power, appearance, multi-tasking, and keyboard options. These all are already very configurable and managed via gliver guile scheme APIs and they are supposed to be fixed.

While it's true that CLIs exist and they are excellent (like ~nmcli/nmtui~ and ~bluetoothctl~), I find myself in need to refer to the help and docs every time I want to use them (TUIs are much more friendly) , such tools are used very rarely and it's hard to remember what needs to be done. Emacs packages are also another viable option.

- Network Manager (via dbus ~org.freedesktop.NetworkManager~)
- Bluetooh Manager (via dbus ~org.bluez~)
- Sound Manager (via unix socket ~/run/user/$UID/pipewire-0~ or ~wpctl~)

** community
currently I am in favor of irc, while it lacks some modern features, it's more than enough for our purpose. Many users are most likely ~guix~ and ~emacs~ users which means they will have their own clients to connect to the libera channel ~#gliver~. However, to be more friendly to newcomers, I am thinking there should be an extensions (probably downloadable, not part of gliver) that will use gleui to create a custom simple irc client, users can configure nickname, and by default it will connect to ~#gliver~ and be able to have very basic features like retrieving archive logs, notifications, copy-pasting, uploading snippets, opening URLs. This should make it easier for newcomers to join the community and use IRC without all of its complexity that's not trivial to users used to modern instant chatting like ~matrix~ or ~discord~.

** gleui
I like the recent improvements, it taught me that gleui if improved further to cover more use-cases, may actually be a very fun UI framework for ~gliver~ simple applications. I don't have plan to extend that as it's currently ~Wayland~ native, to make it work on other environments (including ~x11~) won't be an easy task I guess. There are much better tools for such task like ~gtk~, ~gliver~ uses gleui for better control and to keep the footprint of resources utilization at its best and reduce dependencies.
