* all symbols should be prefixed with the module name

Reason: avoid invalid resolution of symbol name

* define keys using defined functions rather than lambda

DON'T
#+begin_src scheme
  (define-key *top-map* "s-h" (lambda () (cmd-container-focus-direction 'left)))
#+end_src

DO
#+begin_src scheme
  (define (cmd-container-focus-left)
    "Focus the container in the left direction."
    (cmd-container-focus-direction 'left))

  (define-key *top-map* "s-h" cmd-container-focus-left)
#+end_src

Reason: the ability to have proper procedure name and description
Logging will also reflect this

#+begin_src
Key pressed: key=s-h action=#<anonymous procedure> mode=normal persist=#f
Key pressed: key=s-h action=cmd-container-focus-left mode=normal persist=#f
#+end_src

* add hooks using function symbols rather than function reference or lambda

Reason: more friendly repl experience allowing overwriting the hook function to be applied rather than referencing the old implementation which requires updating the hooks as well.

* always perform guard checks and validation to avoid exceptions

Reason: if an exception is expected, also catch it and log errors. Gliver shouldn't crash even if user extend it via hooks or defining commands.
